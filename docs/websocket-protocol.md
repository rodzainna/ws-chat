# WebSocket protocol reference

Endpoint: `wss://<host>/ws`. Every frame in both directions is a JSON object with a `type` field.

## Why WebSocket messages exist alongside GraphQL at all

Sending, editing, and deleting your own messages happen here, not as GraphQL mutations. They're author-owned and real-time by nature, and this is also where the per-user message rate limiter lives. Room creation/joining, membership, and history fetch stay on [GraphQL](./api.md) — they're naturally request/response and pair with cursor pagination. Admin's "delete any message" is a GraphQL mutation, not a WS frame, on purpose: it's moderation, not the author exercising ownership, and it needs to reach messages the moderator's own socket never sent.

## Connecting

- The access token is read from the httpOnly cookie during the upgrade request — never from a query string, which would risk it leaking into proxy or access logs.
- An unauthenticated upgrade is rejected outright (closed, not admitted as anonymous) — every socket is meant to be keyed by `userId`.
- The `Origin` header is checked against `CORS_ORIGIN`, scoped to the `/ws` path, as defense-in-depth against cross-site WebSocket hijacking.
- A connection is authenticated once, at connect time. A disconnect is scheduled for the moment the refresh token (not the short-lived access token) would expire — killing the socket every 15 minutes on the access token's TTL would defeat the point of a short access token entirely.
- Max raw frame size: 16 KB, enforced independently of the 2000-character message-content cap below.
- Heartbeat: the server pings every open socket roughly every 30s and terminates any that didn't pong since the last one. Without this, a reverse proxy in front of the app can silently drop an idle-looking connection even though the app-level socket is otherwise fine.

## Client → server frames

| `type`   | Fields                           | Notes                                                                                                                                                                                            |
| -------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `join`   | `roomId`                         | Server calls the same `canAccessRoom` check GraphQL's history query uses, before admitting the socket to the room's broadcast group. Replies with `joined` or `error`.                           |
| `leave`  | `roomId`                         | Removes the socket from the room's broadcast group. No ack frame.                                                                                                                                |
| `send`   | `roomId`, `content`              | 2000-char cap, enforced server-side regardless of what the client's own form allows. Parses `@mentions` against the room's actual membership. Subject to the per-user token-bucket rate limiter. |
| `edit`   | `roomId`, `messageId`, `content` | Author-only; rejected if the message was already deleted.                                                                                                                                        |
| `delete` | `roomId`, `messageId`            | Author-only. Deleting _someone else's_ message is the GraphQL `deleteMessage` admin mutation, not this.                                                                                          |

A frame with an unrecognized `type`, invalid JSON, or missing/malformed fields for its type gets an `error` frame back (`INVALID_FRAME` / `INVALID_JSON` / `UNKNOWN_TYPE`) instead of being silently dropped or crashing the connection.

## Server → client frames

| `type`                 | Fields                                                     | Sent when                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ---------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `joined`               | `roomId`                                                   | Ack for a successful `join`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `message_created`      | `message` (full object)                                    | Broadcast to the room on a successful `send`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `message_edited`       | `messageId`, `content`, `editedAt`                         | Broadcast on a successful `edit`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `message_deleted`      | `messageId`                                                | Broadcast on a successful `delete` — own or admin.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `room_deleted`         | `roomId`                                                   | An admin soft-deleted the room. Broadcast _before_ the socket is evicted from the room's registry, so a slow or non-compliant client can't keep acting in a room that's already gone from the DB.                                                                                                                                                                                                                                                                                                                                                                                                                |
| `removed_from_room`    | `roomId`                                                   | <a id="removed_from_room"></a>An admin removed this user from the room via `removeRoomMember`. Sent to **every** open socket this user has, not just ones joined to that room — their room sidebar isn't scoped to any one room, so it needs to hear about this regardless of what they're currently viewing. Live eviction from the room's registry stays scoped to sockets actually joined to it: without that step, a removed member with an already-open tab on the room would keep full read/write access, since the registry (not the DB row) is what an in-flight `send`/`edit`/`delete` actually checks. |
| `added_to_room`        | `roomId`                                                   | Sent directly to the added user's own socket(s) after a successful `addRoomMember` — wherever they are in the app. Tells their room sidebar a new room just became visible; carries no other data, since the client refetches `rooms` to get it.                                                                                                                                                                                                                                                                                                                                                                 |
| `room_members_changed` | `roomId`                                                   | Broadcast to everyone currently joined to the room after a successful `addRoomMember` or `removeRoomMember`, so an already-open member list (`roomMembers`) refetches instead of going stale until the next manual reload.                                                                                                                                                                                                                                                                                                                                                                                       |
| `session_expired`      | `reason`: `deactivated` \| `token_expired` \| `logged_out` | Sent immediately before the server force-closes the socket.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `presence_changed`     | `userId`, `online`                                         | Broadcast to every room a user belongs to when their overall connection count crosses 0↔1 (any open socket, any tab/device) — not persisted, always derived live.                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `room_activity`        | `roomId`, `messageId`, `mentionsYou`                       | Sent to a member's socket(s) for a room they belong to but aren't currently joined to, on a successful `send` in it. Drives unread/mention badges on the room list without opening a socket per room.                                                                                                                                                                                                                                                                                                                                                                                                            |
| `error`                | `code`, `message`                                          | Malformed frame, authorization failure, or rate-limit rejection. `code` is one of `INVALID_FRAME`, `INVALID_JSON`, `UNKNOWN_TYPE`, `NOT_FOUND`, `NOT_IN_ROOM`, `FORBIDDEN`, `INVALID_CONTENT`, `RATE_LIMITED`, `INTERNAL_ERROR`.                                                                                                                                                                                                                                                                                                                                                                                 |

## Reconnection

- A token refresh does a "make-before-break" swap: a new, freshly-authenticated socket connects and re-joins the active room before the old one closes, so an access-token rotation is never visible as a dropped connection. Clients dedupe `message_created` by id for the brief window both sockets are alive.
- An _unexpected_ drop (network blip, server restart) does not auto-reconnect — a dead connection surfaces as "Connection lost, reload the page." Not an oversight: proper reconnection needs backoff, re-joining every previously open room, and reconciling any messages missed during the gap, which was more scope than this project's timeline allowed for beyond the refresh-triggered swap above.
